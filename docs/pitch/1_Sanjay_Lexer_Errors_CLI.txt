READ THIS FIRST: WHAT THE PROJECT IS (even if you did nothing)
------------------------------------------------------------
Lumen is a small programming language we built, plus the compiler for it. In most languages a number is just a
number: 9.8 could be metres, seconds or dollars, and the computer cannot tell. In Lumen a number carries its unit:
"9.8 m/s^2" or "12.5 lbf*s" or "250 USD". The compiler checks the units the way a physics teacher checks your
working: you cannot add metres to seconds, and if you pass pound-force-seconds where newton-seconds are needed, it
either converts correctly or refuses to compile. After the check, the units are thrown away, so the program that
actually runs is plain arithmetic.

Why it matters: in 1999 NASA lost the Mars Climate Orbiter ($327.6 million) because one program gave a number in
pound-force seconds and another read it as newton-seconds, a factor of 4.45. In 1983 an Air Canada plane ran out of
fuel because 1.77 (pounds per litre) was used as if it were kg per litre. To an ordinary compiler those numbers are
just "float", so nothing could warn anyone. In Lumen both mistakes are compile errors.

The compiler is a pipeline of seven phases, each in its own file:
  lexer -> parser -> unit checker -> intermediate code (IR) -> optimizer -> bytecode -> virtual machine (VM)
You own the very first phase (the lexer) and also the part that talks to the user: error messages and the command
line. Everything below is in your files: lexer.py, tokens.py, errors.py, cli.py, compiler.py (about 590 lines).

[YOUR PART: LEXER]
"The lexer reads the source text one character at a time and groups the characters into tokens, which are the words
of the language. Take the line 'let g = 9.8 m/s^2;'. The lexer produces: LET, IDENT g, ASSIGN, FLOAT 9.8, IDENT m,
SLASH, IDENT s, CARET, INT 2, SEMI. Every token remembers its line and column, so that later phases can point at
the exact spot when something is wrong."

"Three design points. First, longest match: if the text says '<=', that is one token, not '<' followed by '='.
Second, numbers are stored as exact fractions, not floating point, so 0.1 is exactly one tenth. That matters
because unit conversion factors like 1609.344 metres per mile must not drift. Third, the lexer deliberately does
NOT decide whether a name is a unit. In '9.8 m/s^2' it just sees names and symbols. The parser, which Advaith will
explain, decides that a name right after a number is a unit."

[YOUR PART: ERRORS]
"Errors do not stop the lexer. It records each one and keeps going, so one run reports all of them."

[YOUR PART: COMMAND LINE]

------------------------------------------------------------
QUESTIONS THE PROFESSOR MAY ASK, AND SHORT ANSWERS
------------------------------------------------------------
Q: Why a hand-written lexer and not lex/flex?
A: The language is small, and units need some context-sensitive decisions. A hand-written scanner is a hand-coded
   finite automaton, so every line is explainable, and we get exact control over error messages.

Q: Why are numbers stored as fractions?
A: So conversions are exact. 1 mile = 1609.344 m is stored as an exact fraction and only rounded once, when printed
   or turned into a float at the very end. Floats everywhere would accumulate error.

Q: What does the lexer do with a unit like m/s^2?
A: It does not treat it as a unit. It emits IDENT m, SLASH, IDENT s, CARET, INT 2. The parser decides.

Q: Why are lexical errors reported on their own, without syntax errors?
A: If a character is illegal the token stream is damaged, and parsing it would only create misleading follow-on
   errors. So we stop and report the real problem first.

Q: How does the compiler know the line and column of an error?
A: Every token stores its line and column when the lexer creates it, and every AST node keeps its tokens' positions.

Q: What if the file does not exist?
A: The CLI prints a message and exits with code 2. It never crashes.

Q: What is a Diagnostic?
A: One problem report: severity (error or warning), message, line, column, underline length, optional help text,
   and the phase that found it.
